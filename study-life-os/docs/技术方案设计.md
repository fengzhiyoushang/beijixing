# StudyLifeOS 个人学习·工作·生活管理终端 —— 完整技术方案设计

> 版本：v1.0 ｜ 状态：设计定稿，代码分步实施中
> 三端一体：Web 深度管理端 + 微信小程序轻量采集端 + Python FastAPI 统一后端
> AI 底座：DeepSeek 开放 API（对话 / Function Call 工具调用 / RAG 知识库问答）

---

## 1. 项目概述与产品定位

| 端 | 定位 | 关键词 |
|---|---|---|
| **Web 电脑端** | 深度管理与数据分析中心 | 深色极客风、左侧固定导航、总览仪表盘、右下角常驻悬浮 AI 助手、图表分析、完整 CRUD |
| **微信小程序端** | 随身查询与数据采集入口 | 课表查询、上课提醒、DDL 倒计时、拍照标注空教室、学习打卡、快速录入 |
| **后端** | 唯一数据源 + AI 编排层 | FastAPI、MySQL、Redis、DeepSeek API、JWT 鉴权、REST + SSE |

核心设计原则：

1. **单后端、双消费端**：所有业务数据只落在后端 MySQL；小程序只做"轻录入 + 查询"，Web 做"重编辑 + 分析"，天然避免双端写冲突。
2. **AI 全链路**：AI 不是独立聊天玩具，而是横切能力——悬浮助手通过 Function Call 读写全部 8 个模块的数据；知识库走 RAG；考研规划走结构化 Prompt 工程。
3. **可降级运行**：本地开发无 MySQL/Redis 时自动回退 SQLite + 进程内缓存，一条命令即可跑通全栈，生产切换 MySQL/Redis 只改环境变量。

### 2.1 请求流转约定

- 统一前缀 `/api/v1`；认证：`Authorization: Bearer <JWT>`；注册/登录/wx-login 除外。
- 响应统一为资源本体 JSON（FastAPI + Pydantic 直接序列化），错误用 `{"detail": "..."}` + 标准 HTTP 状态码，前端拦截器统一提示。
- AI 对话支持两种模式：`POST /ai/chat`（JSON 一次性返回，小程序用）与 `POST /ai/chat/stream`（SSE 流式，Web 悬浮窗用）。

## 3. 技术选型与理由

### 3.1 后端

| 选型 | 用途 | 理由 |
|---|---|---|
| FastAPI | Web 框架 | 异步、自动 OpenAPI 文档、Pydantic 校验，前后端契约即代码 |
| SQLAlchemy 2.x | ORM | 成熟稳定，SQLite/MySQL 一行 URL 切换，支撑"可降级运行"策略 |
| MySQL 8 (SQLite 回退) | 主存储 | 生产标准；开发零依赖 |
| Redis 7 (内存回退) | 缓存/计数器/限流 | 仪表盘聚合缓存、AI 会话上下文缓存；回退实现同接口 |
| PyJWT + hashlib(PBKDF2) | 鉴权/口令 | 零 C 依赖，Windows 本地安装不出错 |
| httpx | DeepSeek 调用 | 支持 SSE 流式透传 |
| python-multipart | 文件上传 | 教室照片、知识库文档 |
| openpyxl / python-docx | 文档解析 | Excel 课表导入、docx 知识库入库 |
| Pydantic Settings | 配置 | `.env` 驱动，双端差异只靠环境变量 |

### 3.2 Web 端

| 选型 | 用途 |
|---|---|
| Vue 3 (`<script setup>`) + Vite 5 | SPA 框架与构建 |
| Naive UI（darkTheme + 自定义极客色板） | 组件库，主题定制对深色最友好 |
| ECharts 5 | 仪表盘/统计分析图表 |
| Pinia | 用户态、AI 会话态 |
| Vue Router 4 | 左侧导航路由 + 登录守卫 |
| Axios | REST 请求 + JWT 拦截器 |
| 原生 fetch + ReadableStream | SSE 消费 AI 流式回复 |

### 3.3 小程序端

| 选型 | 用途 |
|---|---|
| 微信原生小程序 | 官方能力（订阅消息、拍照、扫码）无损 |
| Vant Weapp | UI 组件（需 npm 构建，微信开发者工具一键） |
| wx.request 封装层 | 统一 baseURL、JWT、401 重登 |

## 5. 数据模型设计（MySQL DDL 级字段定义）

> 通用约定：主键 `INT AUTO_INCREMENT`；`user_id` 外键到 `users`；时间列 MySQL 用 `DATETIME`，SQLite 回退用 `TEXT`（由 ORM 适配）；JSON 列 MySQL 用 `JSON`，SQLite 用 `TEXT`。

### 5.1 用户

**users**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| username | VARCHAR(64) UNIQUE | 登录名 |
| nickname | VARCHAR(64) | 昵称 |
| password_hash | VARCHAR(255) | PBKDF2-HMAC-SHA256 |
| wx_openid | VARCHAR(64) UNIQUE NULL | 小程序 openid |
| avatar | VARCHAR(255) NULL | 头像 |
| created_at | DATETIME | |

### 5.2 课程表模块

**courses**：id, user_id, name(课程名), teacher(教师), location(上课地点/教室), color(主题色), remark, created_at

**class_slots**（一门课多个上课时段——冲突检测的基本单位）：id, course_id(FK), weekday(1~7), start_time("08:00"), end_time("09:40"), weeks("1-16周" 文本), start_week, end_week

**冲突检测规则**：同一 user 下不同课程，`weekday` 相同且时间区间重叠且周次区间相交 → 冲突对列表（Web 编辑保存时调用，小程序只读）。

### 5.3 DDL 任务模块

**tasks**：id, user_id, title, description, category(`study|work|life`), priority(`high|medium|low`), due_at(DATETIME), status(`pending|done|canceled`), done_at, progress(0~100), tags(JSON 数组), created_at, updated_at

统计口径：完成率 = done/(全部未取消)；逾期 = status=pending 且 due_at<now；倒计时由客户端本地计算 + 列表接口返回 `due_at` 与 `remaining_seconds`。

### 5.4 空教室模块

**classroom_records**（采集的唯一入口，小程序拍照标注）：id, user_id, building(教学楼), room(教室号), occupied(0 空闲/1 占用), photo_url(上传后相对路径), note, weekday(快照时), hour(快照时), visited_at

**规律分析算法**（Web）：按 `(building, room, weekday, hour)` 分桶聚合 → 空闲率 = 空闲记录数/总记录数；**空闲预测** = 空闲率加权（近期记录指数权重）∩ 该时段无本人课程 ∩ 无全校课程占用（class_slots 命中视为低概率）→ 输出 0~100 置信分。数据不足时返回"历史数据不足"提示，不硬编码。

### 5.5 学习打卡模块

**checkin_records**：id, user_id, subject(科目/内容), minutes(专注分钟), content(日志), date(索引), mood(1~5 可空), created_at

连续天数（streak）与月历聚合从该表计算，Redis 缓存当日值（回退内存）。

### 5.6 考研目标与规划模块

**kaoyan_goals**：id, user_id, target_school, target_major, target_year, exam_date(默认 12 月下旬), total_target, total_current, detail(JSON: 各科目 target/current/max, 如政治/英语/数学/专业课), status(`active|achieved|archived`), created_at, updated_at

**plan_phases**：id, goal_id, name(阶段名：基础/强化/冲刺), start_date, end_date, objective(阶段目标文本), focus(JSON), status, sort_no

**plan_tasks**：id, phase_id, date(每日拆解归属日), title, subject, planned_minutes, done(bool), done_minutes, review_note(当日复盘文本), created_at

流程：目标录入 → `POST /kaoyan/gap-analysis`（数值差距表 + DeepSeek 诊断报告）→ `POST /kaoyan/plan/generate`（按剩余天数与差距生成 2~4 个阶段）→ 阶段展开为每日 `plan_tasks` → 每日勾选 + `POST /kaoyan/review`（周复盘 AI 生成）。

### 5.7 知识库模块

**knowledge_docs**：id, user_id, title, category(标签), source(`manual|upload`), file_type(`md|txt|docx|xlsx`), file_url(上传文件相对路径 NULL), content(解析后的纯文本/Markdown 正文，检索与编辑共用), word_count, tags(JSON), last_read_at, read_count, created_at, updated_at

**knowledge_chunks**：id, doc_id, idx, text —— 入库时切块（500 字滑窗 100 重叠），RAG 检索单元。

**RAG 问答**：查询 → 中文二元组 BM25 召回 Top-K chunk → Prompt 注入（引用带 doc 标题）→ DeepSeek 作答 → 返回 answer + references。`POST /ai/chat` 的 `knowledge_search` 工具亦路由到此，实现"AI 助手引用知识库"。

**量化评估指标**：文档数/总字数/分类分布/近 30 天新增曲线/覆盖率(有 chunk 的文档占比)/问答引用频次(read_count 关联)。

### 5.8 个人财务模块

**finance_records**：id, user_id, type(`income|expense`), category(餐饮/交通/学习/娱乐/…), amount(DECIMAL(10,2)), is_study(是否学习投入：购书/课程/文具), note, occurred_at(DATE)

**budgets**：id, user_id, month("2025-08"), category("*"=总预算), limit_amount

**学习投入专项分析**：`is_study=1 ∪ category∈{学习,书籍,课程}` 聚合：金额、占比、Top 科目关键词、月度趋势。

### 5.9 个人健康模块

**health_logs**：id, user_id, kind(`sleep|wake|sedentary|water|exercise|other`), happened_at(DATETIME), minutes(睡眠时长/运动时长), value(水量 ml 等数值), note, date

**health_settings**：id, user_id, sedentary_enabled, sedentary_interval_min(默认 45), quiet_start/quiet_end(免打扰 23:00~7:00), active_start/active_end, updated_at

**久坐提醒链路**：Web/小程序前端心跳 `POST /health/sedentary-heartbeat`；后端判定超过 interval 且不在免打扰时段 → 写入提醒事件并在 `/dashboard/summary` 与 SSE 返回；小程序订阅消息（模板 ID 在 `.env` 配置，未配置时仅站内提醒）。

### 5.10 AI 模块

**ai_sessions**：id, user_id, title(首条消息截断), source(`web|miniapp`), created_at
**ai_messages**：id, session_id, role(`user|assistant|tool`), content(TEXT), tool_name, tool_args(JSON), created_at

Function Call 工具注册表（后端执行，用户隔离）：

| 工具 | 能力 | 读/写 |
|---|---|---|
| `get_today_schedule` | 今日课程 | 读 |
| `list_week_schedule` | 周课表 | 读 |
| `list_tasks` / `create_task` / `complete_task` | DDL 查/建/完成 | 读+写 |
| `create_checkin` / `get_checkin_stats` | 打卡 | 读+写 |
| `get_classroom_status` / `predict_free_room` | 教室状态/预测 | 读 |
| `get_finance_summary` / `add_finance_record` | 财务 | 读+写 |
| `get_kaoyan_progress` | 考研进度 | 读 |
| `knowledge_search` | RAG 检索问答 | 读 |
| `get_dashboard_summary` | 总览 | 读 |
| `get_health_status` / `log_health` | 健康 | 读+写 |

系统 Prompt：注入当前日期、用户昵称、模块数据快照摘要（Redis 缓存 5 分钟），约束"需要数据时先调用工具"。

## 6. API 路由清单（`/api/v1`）

### 6.1 认证 auth

## 7. AI 能力设计要点

1. **DeepSeek Client**：`httpx.AsyncClient` 指向 `https://api.deepseek.com`；`chat(messages, tools, stream)`；无 API Key 时进入 **mock 降级**（返回"未配置 Key"提示 + 直接执行用户意图明显的数据查询并格式化返回），保证联调期全链路不断。
2. **Function Call 循环**（上限 4 轮）：模型返回 `tool_calls` → 服务端以 **当前 JWT 用户的身份**执行工具（权限天然隔离）→ 结果以 `role=tool` 回填 → 继续生成；SSE 模式将每步 `tool` 事件透传给前端可视化展示"正在查询你的课表…"。
3. **RAG**：零外部依赖的中文二元组分词 + BM25（Python 实现，存 `knowledge_chunks`），Embedding/向量库列为二期演进项（方案预留 `rag.py` 的接口签名）。
4. **结构化规划生成**：考研 gap-analysis 与 plan/generate 先用规则引擎算数值差距/阶段时间窗，再让 DeepSeek 输出 Markdown 建议，**数值不依赖模型**，防止幻觉。

## 8. 双端数据联动策略

- **同源只读**：小程序查询与 Web 查询打同一组 GET 接口；Web 深度编辑后小程序下次拉取即最新（小程序课表页 `onShow` 静默刷新）。
- **采集互补**：打卡/DDL 快速录入/教室拍照以小程序写入为主，Web 端展示同一数据；不做本地持久缓存，避免双端写冲突。
- **提醒下发**：上课提醒 = 小程序启动/前台时拉 `/courses/today` + 订阅消息（模板 ID 配 `.env`）；DDL 提醒 = 订阅消息 + Web 角标轮询 `/tasks/upcoming?within_days=1`。
- **ID 打通**：Web 注册账号 → 小程序 `wx-login` 返回绑定码（openid 绑定到同一 user）；开发期默认绑定演示账号。

## 9. 缓存 / 静态资源 / 配置

- Redis key 规范：`sl:dashboard:{uid}`(TTL 60s)、`sl:ai:ctx:{sid}`(会话上下文 TTL 1h)、`sl:streak:{uid}:{date}`；`cache.py` 封装 `get/set/delete`，Redis 连不上自动降级进程内 TTL dict（单 worker 开发足够）。
- 上传：照片 ≤5MB、文档 ≤10MB，白名单扩展名，落盘 `backend/uploads/{kind}/{yyyymm}/{uuid}.{ext}`，FastAPI `StaticFiles` 挂载 `/uploads`，URL 相对存储（迁移只改 BASE_URL）。
- `.env` 全量清单见 `backend/.env.example`（DB_BACKEND/MYSQL_*/REDIS_URL/DEEPSEEK_API_KEY/WX_APPID/WX_SECRET/SUBSCRIBE_TEMPLATE_ID 等）。

## 10. 安全设计

1. 口令 PBKDF2-HMAC-SHA256（240k 迭代，随机盐）；JWT HS256（`SECRET_KEY`），7 天过期，前端 localStorage / wx storage 保存。
2. 全部业务接口按 `user_id` 过滤，杜绝水平越权；写操作二次校验归属。
3. 上传文件类型白名单 + 重命名 + 存储目录禁执行；CORS 白名单可配置。
4. wx-secret 仅存服务端；code2session 换 openid，不透出。

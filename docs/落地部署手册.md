# 北极星 · 个人战略终端 —— 落地部署手册

> 适用版本：后端 `polaris-backend` 1.0.0（FastAPI + SQLAlchemy + MySQL + Redis + DeepSeek）、
> 前端 `polaris-terminal` 1.0.0（Vue3 + Vite + Naive UI + ECharts）、
> 小程序 `study-life-os/miniprogram`（微信原生 + Vant Weapp）。
>
> 本手册中的命令均已按 Windows / Ubuntu 22.04 实际环境写全路径；所有涉及
> **IP、域名、密码、密钥**的位置一律使用占位符，替换规则见下表。

## 〇、占位符与替换规则（先读这一节）

| 占位符 | 含义 | 替换示例 | 在哪些章节出现 |
|---|---|---|---|
| `<服务器公网IP>` | 云服务器公网 IPv4 | `123.123.123.123` | 三、四、五 |
| `<你的域名>` | 已备案并解析到服务器的域名（不带 `https://`） | `polaris.example.com` | 三、五 |
| `<本机局域网IP>` | 开发机在 WiFi 下的内网地址 | `192.168.1.23` | 二、五 |
| `<MySQL密码>` | MySQL `root`（或专用账号）密码 | 由你生成，建议 16 位以上 | 二、三、六 |
| `<JWT密钥>` | 后端签发 token 的密钥 | `openssl rand -hex 32` 的输出 | 三、七 |
| `<DeepSeek密钥>` | DeepSeek 平台 API Key | `sk-xxxxxxxxxxxxxxxx` | 三、六、七 |
| `<AppID>` | 微信小程序 AppID | `wx1234567890abcdef` | 一、五 |
| `<订阅模板ID>` | 微信订阅消息模板 ID | `ABCDef...` | 五 |

> 全部占位符都写成尖括号形式，**复制命令后请务必先整体替换再执行**。
> 文中出现 `admin` / `admin123` 是初始化脚本写入的**演示账号**，上线前必须改密码。

### 1.3 上线前的三条硬性约束

1. 小程序的 `wx.request` **只能请求 HTTPS 域名**（开发者工具里可临时勾选「不校验合法域名」，真机预览/发布必须配置合法域名）。
2. 合法域名必须在 ICP 备案主体名下，且**域名与证书一致**（自签证书一律不通过）。
3. 合法域名配置后**每月只能修改 5 次**，请一次配准。

## 二、路线 A：本机 / 局域网自用（零成本）

**适用**：自己电脑长期开着跑、手机连同一 WiFi 访问。全部功能可用（除微信订阅消息推送）。

### 2.1 前置：安装运行环境（Windows）

| 依赖 | 版本要求 | 验证命令 | 期望输出 |
|---|---|---|---|
| Python | 3.10 及以上（推荐 3.12） | `python --version` | `Python 3.12.x` |
| Node.js | 18 及以上 | `node -v` | `v18.x` / `v20.x` |
| pnpm 或 npm | 任一 | `pnpm -v` 或 `npm -v` | 有版本号即可 |
| 微信开发者工具 | 最新稳定版 | — | 能打开小程序项目 |

> 后端 MySQL / Redis **都不是必需的**：MySQL 连不上会自动回退 SQLite（`data/polaris.db`），
> Redis 连不上会自动回退进程内缓存。

### 2.2 启动后端（监听所有网卡，供手机访问）


## 三、路线 B：公网服务器常驻（Ubuntu 22.04 为例）

**适用**：需要随时随地从手机/任意电脑访问，且要用小程序正式版。
**前提**：域名已备案、已解析到 `<服务器公网IP>`（A 记录）。

### 3.1 服务器安全组 / 防火墙

在云厂商控制台安全组放行入站：`22`（SSH，建议限制来源 IP）、`80`、`443`。
**不要**放行 `3306`、`6379`、`8000` —— 这三个只允许本机访问。

```bash
# 服务器系统防火墙（Ubuntu 默认 ufw 可能未启用）
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw status
```

### 3.2 安装系统依赖

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-venv python3-pip nginx git mysql-server redis-server certbot python3-certbot-nginx
python3 --version          # 期望 Python 3.10.x（Ubuntu 22.04 自带）
```

### 3.3 创建数据库与专用账号

```bash
# 1) 进入 MySQL（Ubuntu 的 root 默认走 auth_socket，用 sudo 登录）
sudo mysql

# 2) 在 MySQL 交互界面里执行（把 <MySQL密码> 换成你自己的强密码）
CREATE DATABASE IF NOT EXISTS polaris_terminal
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'polaris'@'localhost' IDENTIFIED BY '<MySQL密码>';
GRANT ALL PRIVILEGES ON polaris_terminal.* TO 'polaris'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

> 后端用的是 **PyMySQL**（纯 Python 驱动），MySQL 8 的 `caching_sha2_password` 由
> `cryptography` 包支持，已在 `requirements.txt` 中，无需额外配置。

Redis 只需本机监听（Ubuntu 的默认配置已符合）：

```bash
sudo systemctl enable --now mysql redis-server
sudo systemctl status mysql --no-pager
redis-cli ping          # 期望 PONG
```

### 3.4 拉取代码并安装依赖

```bash
sudo mkdir -p /opt/polaris-backend
sudo chown -R $USER:$USER /opt/polaris-backend

# 用你的 Git 仓库地址；若是 scp/rsync，把整个 polaris-backend 目录传到 /opt/polaris-backend
git clone <你的仓库地址> /opt/polaris-backend
cd /opt/polaris-backend

python3 -m venv .venv
.venv/bin/pip install --upgrade pip -i https://mirrors.aliyun.com/pypi/simple/
.venv/bin/pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

### 3.5 配置 `.env`（关键一步）

```bash
cd /opt/polaris-backend
cp .env.example .env
vim .env
```

必改项（其余保持默认即可）：

```ini
# ── 数据库：改为 MySQL 模式，指向本机 ──
DB_BACKEND=mysql
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=polaris
MYSQL_PASSWORD=<MySQL密码>
MYSQL_DB=polaris_terminal

# ── Redis ──
REDIS_URL=redis://127.0.0.1:6379/0
REDIS_ENABLED=true

# ── 安全：JWT 密钥必须换掉（在线生成：openssl rand -hex 32）──
JWT_SECRET=<JWT密钥>
ACCESS_TOKEN_EXPIRE_MINUTES=10080

# ── DeepSeek ──
DEEPSEEK_API_KEY=<DeepSeek密钥>

# ── 生产环境建议关闭 DEBUG（关闭后日志级别为 INFO）──
DEBUG=false

# ── CORS：公网部署时前后端同域，经 Nginx 反代，理论不触发跨域；仍建议显式写域名 ──
CORS_ORIGINS=https://<你的域名>
```

> `.env` 权限收紧：`chmod 600 /opt/polaris-backend/.env`
> 后端入口是 `app.main:app`，接口前缀 `/api/v1`，上传静态目录 `/uploads`，健康检查 `/health`。

### 3.6 初始化数据库

```bash
cd /opt/polaris-backend
.venv/bin/python scripts/init_db.py --seed     # 建库 + 建表 + 演示数据（幂等，可重复执行）
.venv/bin/python scripts/init_db.py --stats    # 查看各表行数
# 危险操作：重建（会清空业务数据）
# .venv/bin/python scripts/init_db.py --drop --seed
```

看到 `✓ 建表完成：engine=mysql backend=mysql` 即为成功。
随后用管理员账号登录 Web 端，**立即修改 `admin` 的密码**。

### 3.7 systemd 常驻（后端）

```bash
sudo mkdir -p /opt/polaris-backend/{uploads,backups,data}
sudo chown -R www-data:www-data /opt/polaris-backend

# 复制本仓库提供的单元文件
sudo cp /opt/polaris-backend/deploy/polaris.service /etc/systemd/system/polaris.service
sudo systemctl daemon-reload
sudo systemctl enable --now polaris
sudo systemctl status polaris --no-pager

# 验证与排错
curl http://127.0.0.1:8000/health
journalctl -u polaris -f            # 实时日志
```

单元文件要点（可在 `deploy/polaris.service` 中查看完整注释）：
`WorkingDirectory=/opt/polaris-backend`、`User=www-data`、
`ExecStart=/opt/polaris-backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2`、
`Restart=always`、`Environment=PYTHONIOENCODING=utf-8`、
`After=network.target mysql.service redis-server.service`。

> 若改用 SQLite（`DB_BACKEND=sqlite`），请把 `--workers` 改为 `1`，否则多进程写同一 db 文件会报 `database is locked`。

### 3.8 部署前端 `dist/` 并配置 Nginx + HTTPS

**① 本地构建前端**（在你自己的开发机上）：

```powershell
cd "F:\deepseek harness  wenjian\polaris-terminal"
pnpm install
pnpm build            # 产物输出到 polaris-terminal\dist\
```

**② 上传产物到服务器**：

```powershell
# 本地 PowerShell 执行（<服务器公网IP> 替换为实际 IP）
scp -r "F:\deepseek harness  wenjian\polaris-terminal\dist" root@<服务器公网IP>:/tmp/polaris-dist
```

```bash
# 服务器执行
sudo mkdir -p /opt/polaris-terminal
sudo rm -rf /opt/polaris-terminal/dist
sudo mv /tmp/polaris-dist /opt/polaris-terminal/dist
sudo chown -R www-data:www-data /opt/polaris-terminal
```

**③ 配置 Nginx**：

```bash
sudo cp /opt/polaris-backend/deploy/nginx.conf /etc/nginx/sites-available/polaris.conf
sudo vim /etc/nginx/sites-available/polaris.conf
#   把文件里 3 处 your.domain.com 全部替换为 <你的域名>
#   （建议直接用 vim 一次替换：:%s/your.domain.com/你的域名/g）
#   证书路径 /etc/letsencrypt/live/your.domain.com/ 会随域名一起被替换
sudo ln -sf /etc/nginx/sites-available/polaris.conf /etc/nginx/sites-enabled/polaris.conf
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
```

配置中的关键路径（与 3.7、3.8② 完全一致）：

| 用途 | 配置项 | 路径 |
|---|---|---|
| 前端静态根目录 | `root` | `/opt/polaris-terminal/dist` |
| SPA 回退 | `try_files $uri $uri/ /index.html` | — |
| 上传文件 | `alias` | `/opt/polaris-backend/uploads/` |
| API 反代 | `proxy_pass` | `http://127.0.0.1:8000` |
| 上传上限 | `client_max_body_size` | `30m`（后端单文件上限 20MB，留余量） |
| SSE 流式 | `proxy_buffering off; proxy_read_timeout 300s;` | 单独作用于 `POST /api/v1/ai/chat/stream` |

**④ 签发 HTTPS 证书**：

```bash
sudo certbot --nginx -d <你的域名>
# 按提示填邮箱、同意条款、选择「重定向 HTTP 到 HTTPS」
sudo certbot renew --dry-run        # 验证自动续期（certbot 自带定时器）
sudo systemctl reload nginx
```

**⑤ 验收**：

```bash
curl -I https://<你的域名>                      # 期望 200，且是 HTML
curl https://<你的域名>/api/v1/ai/status        # 期望返回模型/向量 provider 信息
curl -I http://<你的域名>                        # 期望 301 跳转到 https
```

## 四、路线 C：微信云托管（免备案、免运维）

**适用**：不想买服务器、不想等备案，接受按量计费。平台自带 HTTPS 域名，无需自己申请证书。

### 4.1 为什么能免备案

微信云托管提供平台默认域名（形如 `xxx-yyy.ap-shanghai.run.tcloudbase.com`），
该域名由腾讯云持有并已备案，你直接把它填进小程序「合法域名」即可，**不需要自己做 ICP 备案**。
代价：不能绑定自定义域名（除非自定义域名自身已备案）。

### 4.2 部署后端镜像

```bash
# ① 本地/CI 构建镜像（使用本仓库 polaris-backend/Dockerfile）
cd "F:\deepseek harness  wenjian\polaris-backend"
docker build -t polaris-backend:1.0.0 .

# ② 推到腾讯云容器镜像服务（在云托管控制台「镜像仓库」里可看到推送指引与地址）
docker login ccr.ccs.tencentyun.com
docker tag polaris-backend:1.0.0 ccr.ccs.tencentyun.com/<命名空间>/polaris-backend:1.0.0
docker push ccr.ccs.tencentyun.com/<命名空间>/polaris-backend:1.0.0
```

在云托管控制台：

1. 新建服务（例如 `polaris-api`）→ 部署方式选「镜像」→ 选刚推送的镜像。
2. 端口填 **8000**（与 Dockerfile 的 `EXPOSE 8000` 一致）。
3. 环境变量（**不要**照抄 `.env` 里的 `127.0.0.1`）：
   - `DB_BACKEND=mysql`，`MYSQL_HOST=<云托管 MySQL 内网地址>`，`MYSQL_PORT=3306`，
     `MYSQL_USER=polaris`，`MYSQL_PASSWORD=<MySQL密码>`，`MYSQL_DB=polaris_terminal`
   - `REDIS_URL=redis://<云托管 Redis 内网地址>:6379/0`（或用平台 Redis 提供的连接串）
   - `JWT_SECRET=<JWT密钥>`、`DEEPSEEK_API_KEY=<DeepSeek密钥>`、`DEBUG=false`
   - `UPLOAD_DIR=uploads`、`BACKUP_DIR=backups`
   - 注意：云托管的容器文件系统**非持久**，`uploads/`、`backups/` 必须挂载
     COS 对象存储或云硬盘，否则重建实例后文件与备份丢失。
4. 记录平台给出的**默认 HTTPS 域名**，形如 `https://<云托管默认域名>`。

### 4.3 初始化数据库（一次性）

云托管不提供稳定的交互式终端时，用两种方式之一：

- **方式一（推荐）**：把初始化逻辑放到一个临时容器/一次性任务里执行
  `python scripts/init_db.py --seed`，执行完删除该任务。
- **方式二**：从你的电脑用 MySQL 客户端直连云数据库公网地址（若已开启公网），
  执行建库后，再在 API 服务里用云托管控制台的「WebShell / 远程调试」执行
  `python scripts/init_db.py`（不带 `--seed`，只建表）。

验证：浏览器打开 `https://<云托管默认域名>/health`，期望 `status: ok`。

### 4.4 定时触发器跑提醒推送

云托管控制台 → 服务 → **定时触发器**：

| 项 | 值 |
|---|---|
| Cron 表达式 | `0 */10 * * * *`（云托管使用 **6 段** Cron：秒 分 时 日 月 周） |
| 执行命令 | `python scripts/push_reminders.py` |
| 超时 | 60 秒 |

> **关于 `scripts/push_reminders.py`**：该脚本已存在，位于
> `polaris-backend/scripts/push_reminders.py`（扫描即将到期的 DDL 任务与临近的上课时间，
> 按「一次性订阅额度」下发微信订阅消息）。它支持三个参数：
>
> ```bash
> python scripts/push_reminders.py              # 同时扫 DDL + 上课（默认）
> python scripts/push_reminders.py --kind ddl   # 只扫 DDL
> python scripts/push_reminders.py --kind class # 只扫上课提醒
> python scripts/push_reminders.py --ahead 60   # 临时覆盖「提前 N 分钟」配置
> ```
>
> 脚本读取与 API 相同的 `.env`：若 `WX_APPID` / `WX_APP_SECRET` 未配置，它会打印
> `! 未配置 WX_APPID/WX_APP_SECRET，本次只记录日志不会真实发送` 并以演示模式结束（不会报错）。
> 前提是用户的订阅授权额度还没用完——每次授权只能推一条，额度查看见
> `GET /api/v1/wechat/quota`。
>
> 同样的提醒扫描在本机/自建服务器上也可以用 crontab 实现，示例见
> `polaris-backend/deploy/push-reminders.cron`（每 10 分钟一次，日志写入 `backups/push.log`）。

### 4.5 云托管注意点

- 冷启动：无流量一段时间后实例会缩容，首次请求可能慢 3~10 秒；可在控制台把最小实例数设为 1。
- 日志：控制台「日志」页可按请求 ID 检索，排查 500 比自建服务器更方便。
- 计费：按 CPU/内存用量与调用次数计费，个人自用通常每月几元到几十元。
- 由于容器非持久，`backups/` 目录里的 JSON 备份请定期下载或转存对象存储（见第七章 7.1）。

### 5.2 服务器域名配置（正式版必须）

微信公众平台 → 开发 → 开发管理 → 开发设置 → **服务器域名**：

| 类型 | 填什么 | 本项目用到的接口 |
|---|---|---|
| **request 合法域名** | `https://<你的域名>`（云托管则填平台默认域名） | 全部 `/api/v1/...` 接口，包括 `POST /api/v1/auth/login`、`POST /api/v1/auth/wx-login`、`GET /api/v1/courses/today`、`GET /api/v1/tasks/upcoming` |

| **downloadFile 合法域名** | 同上 | 下载备份文件 `GET /api/v1/system/backups/{backup_id}`（若小程序需要） |
| **socket 合法域名** | 本项目不用 WebSocket，可留空 | — |

注意事项：

- 必须是 **HTTPS**，且证书链完整。IP 地址、`http://`、自签证书、端口号非 443 的地址都不能配。
- 域名必须已完成 ICP 备案（云托管默认域名除外）。
- 每月**只能修改 5 次**合法域名，配置前先想清楚。
- 开发阶段可在开发者工具「详情 → 本地设置」勾选「不校验合法域名…」先行联调。

### 5.3 上传相关额度

- 后端单文件上限由 `.env` 的 `MAX_UPLOAD_MB` 控制，默认 `20`（MB）。
- Nginx 的 `client_max_body_size` 设为 `30m`，留出 multipart 包装余量。
- `wx.uploadFile` 单文件上限约 10MB，教室照片通常远小于此；知识库大文档建议在 Web 端上传。

### 5.4 订阅消息模板申请与「一次性订阅」的限制

**申请步骤**：

1. 微信公众平台 → 功能 → **订阅消息** → 公共模板库，搜索「任务提醒 / 待办提醒 / 课程提醒」等关键词。
2. 选择合适的模板（需要「任务名称 / 提醒时间 / 备注」之类的字段），点「选用」。
3. 在「我的模板」里复制**模板 ID**，填到后端 `.env`：
   - DDL 到期提醒模板 → `WX_TEMPLATE_DDL=<订阅模板ID>`
   - 上课提醒模板 → `WX_TEMPLATE_CLASS=<订阅模板ID>`
   改完重启后端（`sudo systemctl restart polaris` 或 `docker compose restart api`）。
4. 若要让后端真正调用发送接口，还需在「开发管理 → 开发设置」获取 **AppSecret**，
   填入 `.env` 的 `WX_APPID=<AppID>` 与 `WX_APP_SECRET=<AppSecret>`。
   **未配置时后端进入演示模式**：只写推送日志、不实际发送（方便本地联调，不会报错）。
5. 小程序端与后端的订阅链路由 `/api/v1/wechat/*` 支撑，可用下面接口自查：

   | 接口 | 用途 |
   |---|---|
   | `GET /api/v1/wechat/status` | 订阅消息配置状态（AppID / 模板 / 定时任务是否就绪） |
   | `GET /api/v1/wechat/quota` | 本用户剩余可推送次数（一次性订阅额度） |
   | `POST /api/v1/wechat/subscribe/quota` | 小程序授权成功后上报授权次数 |
   | `POST /api/v1/wechat/push/test` | 发一条测试提醒（会消耗一次配额） |
   | `POST /api/v1/wechat/push/scan` | 立即执行一次扫描（等价于手动跑 `scripts/push_reminders.py`） |
   | `GET /api/v1/wechat/push-logs` | 推送日志（排查「为什么没收到提醒」的首选） |

   `.env` 中与提醒相关的其它开关：`WX_PUSH_ENABLED`（总开关）、
   `WX_DDL_AHEAD_MINUTES`（默认 180 分钟）、`WX_CLASS_AHEAD_MINUTES`（默认 30 分钟）、
   `WX_MP_STATE`（`formal` / `trial` / `developer`，决定推送到正式版还是体验版）、
   `WX_SCHEDULER_ENABLED`（进程内定时扫描，**生产建议 false**，改用 cron 调 `scripts/push_reminders.py`）。

**必须提前知道的限制**：

| 限制 | 说明 |
|---|---|
| **一次性订阅** | 用户每授权一次，你**只能推一条**消息；推完即失效，需要再次授权。想做「每节课都提醒」必须引导用户多次授权，或改用长期订阅（仅政务/医疗等特定类目开放）。 |
| 授权时机 | `wx.requestSubscribeMessage` 必须在**用户点击**等交互回调中调用，不能进页面自动拉起。 |
| 模板不可自造 | 只能用公共模板库或已通过审核的自建模板，字段名固定，传参 key 必须与模板字段对应。 |
| 拒绝授权 | 用户勾选「总是保持以上选择，不再询问」后，后续授权会直接返回拒绝，需要引导其到小程序设置页手动开启。 |
| 频率限制 | 服务端推送接口有日调用量上限，个人小程序量级够用，但不要写成死循环推送。 |

> 未配置模板 ID 时，小程序**不会报错**，只是不发订阅消息；站内提醒（页面上的提醒区）仍然正常。

### 5.5 真机调试注意事项

1. **后端地址**：真机不能用 `localhost`。打开小程序「我的」页，把后端地址改成
   `http://<本机局域网IP>:8000`（路线 A）或 `https://<你的域名>`（路线 B）。
2. **HTTPS 强制**：真机预览时若「不校验合法域名」未生效，`http://` 请求会直接失败。
   最稳妥是走路线 B 的域名 + 证书。
3. **调试开关**：真机预览界面右下角「…」→ 打开调试，才看得到 vConsole 报错。
4. **证书链**：部分安卓机型对中间证书敏感，用 `https://www.myssl.cn/tools/#ssl-check` 之类工具确认
   `fullchain.pem` 完整。
5. **拍照上报**：需要真机授权相机/相册权限；开发者工具里也能选本地图片模拟。
6. **npm 构建**：Vant Weapp 组件（`@vant/weapp`）必须先执行「工具 → 构建 npm」，
   否则页面报组件找不到。

```powershell
docker compose stop                    # 停止（保留数据）
docker compose down                    # 删除容器（数据卷保留，数据不丢）
```

### 6.2 编排说明

| 服务 | 镜像 | 端口 | 持久化 | 健康检查 |
|---|---|---|---|---|
| `api` | 本地构建（`Dockerfile`，python:3.12-slim） | `8000:8000` | `./uploads`、`./backups`、`./data` 挂载 | 调用 `/health` |
| `mysql` | `mysql:8.0`（utf8mb4） | `3306:3306`（公网服务器请注释掉） | 命名卷 `polaris-mysql-data` | `mysqladmin status` |
| `redis` | `redis:7-alpine`（`--appendonly yes`） | 不对外映射 | 命名卷 `polaris-redis-data` | `redis-cli ping` |

- `api` 通过 `depends_on ... condition: service_healthy` 等 MySQL / Redis 健康后才启动。
- `api` 的 `environment:` 已内置容器内地址（`MYSQL_HOST=mysql`、`REDIS_URL=redis://redis:6379/0`）；
  随仓库附带的 `docker-compose.override.yml` 会**自动加载**并再确认一次
  （`environment` 优先级高于 `env_file`）。删除该覆盖文件也不会连不上数据库。
- MySQL 健康检查用 `mysqladmin status`（只看服务是否就绪、不校验密码），
  因此密码含 `$`、`"` 等特殊字符时不会误判。
- 想只用 SQLite 快速体验：`.env` 里设 `DB_BACKEND=sqlite`，然后 `docker compose up -d api`。
- **跨域提醒**：`docker-compose.yml` 中 `api` 的 `CORS_ORIGINS` 默认放行
  `http://localhost:5200`、`http://127.0.0.1:5200`、`http://localhost:5173`
  （与 `.env.example` 一致）。若你的前端首页地址不在其中（例如换了端口、
  改成 `http://<本机局域网IP>:5200`、或用 `http://host.docker.internal:5200` 访问），
  请把该地址补进 `.env` 的 `CORS_ORIGINS`（逗号分隔、无空格、含协议与端口），
  再执行 `docker compose restart api` 生效。注意 `allow_credentials=True` 时不能用 `*`。

### 6.3 Docker 常见报错

| 报错信息 | 原因 | 处理 |
|---|---|---|
| `failed to connect to the docker API at npipe:...` / `Cannot connect to the Docker daemon` | Docker Desktop 未启动 | 启动 Docker Desktop，等鲸鱼图标变绿后重试 |
| `bind: An attempt was made to access a socket ... 8000` / `port is already allocated` | 宿主机 8000/3306/6379 被占用 | 改 `docker-compose.yml` 的端口映射左侧（如 `18000:8000`），或 `netstat -ano \| findstr :8000` 找到占用进程后结束它 |
| `api` 容器反复重启，日志 `Access denied for user 'root'@'...'` | `.env` 中 `MYSQL_PASSWORD` 与 MySQL 容器已初始化的密码不一致 | 密码以 **MySQL 数据卷首次初始化时**的值为准；改 `.env` 后需 `docker compose down -v` 重建数据卷（会清空数据） |
| `api` 日志 `MySQL 连接失败…已回退 SQLite` | `MYSQL_HOST` 仍是 `127.0.0.1` | 确认 `docker-compose.override.yml` 存在，或手工把 `MYSQL_HOST` 改为 `mysql` |
| `api` 健康检查一直 `starting` | 数据库初始化较慢 | `docker compose logs api` 看进度；首次构建 + MySQL 初始化通常需 40~90 秒 |
| 表不存在 / `Table 'polaris_terminal.users' doesn't exist` | 未执行数据库初始化 | `docker compose exec api python scripts/init_db.py --seed` |
| 上传文件在容器重建后消失 | 只用了容器内路径 | 确认 `./uploads`、`./backups` 挂载生效（`docker compose config` 可看到卷映射） |
| `no configuration file provided` | 不在 `polaris-backend` 目录 | `cd polaris-backend` 后再执行，或用 `-f` 指定文件绝对路径 |
| 中文乱码 | MySQL 字符集未生效 | compose 已内置 utf8mb4 参数；自建 MySQL 需确认库/表为 `utf8mb4` |

## 七、运维与安全

### 7.1 数据备份

**方式一：接口备份（推荐日常使用，按用户维度）**

```bash
# 1) 先登录拿 token
curl -X POST https://<你的域名>/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"<你的密码>\"}"
# 返回体里的 access_token 复制出来，下面用 <TOKEN> 表示

# 2) 创建备份（scope=user 仅本人数据；scope=full 全库，需管理员）
curl -X POST https://<你的域名>/api/v1/system/backups \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d "{\"scope\":\"user\",\"note\":\"每周例行备份\"}"

# 3) 查看备份列表 / 备份详情
curl -H "Authorization: Bearer <TOKEN>" https://<你的域名>/api/v1/system/backups
curl -H "Authorization: Bearer <TOKEN>" https://<你的域名>/api/v1/system/backups/1

# 4) 删除备份（同时删除服务器上的 json 文件）
curl -X DELETE -H "Authorization: Bearer <TOKEN>" https://<你的域名>/api/v1/system/backups/1
```

备份文件落在 `BACKUP_DIR`（默认 `polaris-backend/backups/`），命名为
`backup-<scope>-<YYYYMMDD-HHMMSS>.json`，内容为 JSON（`meta` + `data` 两段），可直接文本查看。

**方式二：脚本备份（服务器定时任务）**

```bash
# 每天 03:10 做一次全库备份（用 venv 里的 python 执行）
sudo crontab -e
# 写入：
10 3 * * * cd /opt/polaris-backend && /opt/polaris-backend/.venv/bin/python scripts/init_db.py --stats >> /opt/polaris-backend/backups/stats.log 2>&1
```

> 提醒：本仓库 `scripts/` 目前只有 `init_db.py` 与 `seed_demo.py`。
> 若你的部署要定时生成备份文件，请以 `/api/v1/system/backups` 接口为准（用 curl + cron，
> 或写一个调用 `/system/backups` 的小脚本），不要引用不存在的脚本名。

**恢复（危险，务必先在测试库演练）**

```bash
curl -X POST https://<你的域名>/api/v1/system/backups/<backup_id>/restore \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d "{\"confirm\":true}"
```

恢复注意事项：

1. **仅支持 `scope=user` 的备份**；全库备份（`scope=full`）不能通过接口恢复，请走 7.5 的 MySQL 原生恢复。
2. 恢复是「**先按 `user_id` 删除该用户在这些表中的全部数据，再插入备份内容**」，
   即备份之后新产生的数据会被覆盖删除。
3. 恢复涉及 19 张用户维度表，任何一张出错会记录在返回体的 `failed` 字段里，**必须逐条检查**。
4. 恢复前先停写：`sudo systemctl stop polaris`，或让用户停止操作，避免并发写入冲突。
5. 恢复完成后核对：`curl -H "Authorization: Bearer <TOKEN>" https://<你的域名>/api/v1/system/tables`。

### 7.3 DeepSeek 用量与预算

- 控制台看用量：DeepSeek 开放平台 → 用量/账单。
- 后端请求都会带超时与重试（`DEEPSEEK_TIMEOUT` 默认 60 秒，指数退避重试）。
- 想临时关掉真实调用而不影响其他功能：把 `.env` 的 `DEEPSEEK_API_KEY` 留空，
  重启服务即进入**演示模式**（对话返回提示、Function Call 用规则触发工具、识图返回启发式结果）。
- 想减少 RAG 向量化的外部调用：`.env` 设 `EMBEDDING_PROVIDER=local`（零依赖本地哈希向量，不产生费用）。
- `MAX_TOOL_ROUNDS`（默认 4）限制单次对话最多几轮工具调用，调小可显著降低成本。
- **预算建议**：个人自用充值 10~50 元即可；务必在平台设置余额提醒，避免 Key 泄露后被刷。

### 7.5 MySQL 备份与证书续期

**MySQL 逻辑备份（每日 03:30，保留 14 天）**：

```bash
sudo mkdir -p /var/backups/polaris
sudo crontab -e
# 写入下面两行（第二行清理 14 天前的旧备份）
30 3 * * * mysqldump -u polaris -p'<MySQL密码>' --single-transaction --default-character-set=utf8mb4 polaris_terminal | gzip > /var/backups/polaris/polaris_$(date +\%F).sql.gz
40 3 * * * find /var/backups/polaris -name 'polaris_*.sql.gz' -mtime +14 -delete
```

恢复 MySQL 备份：

```bash
sudo systemctl stop polaris                      # 先停写
gunzip -c /var/backups/polaris/polaris_2026-01-01.sql.gz | mysql -u polaris -p'<MySQL密码>' polaris_terminal
sudo systemctl start polaris
```

> 注意：`crontab` 里的 `%` 必须转义成 `\%`，否则 cron 会截断命令。

## 八、排错速查表

| # | 现象 | 可能原因 | 处理 |
|---|---|---|---|
| 1 | 后端日志 `Access denied for user 'polaris'@'localhost' (using password: YES)` | `MYSQL_PASSWORD` 与数据库实际密码不一致；或账号 host 不匹配 | 用 `sudo mysql` 登录后 `ALTER USER 'polaris'@'localhost' IDENTIFIED BY '<新密码>';` 并同步改 `.env`；Docker 版若改过密码需 `docker compose down -v` 重建数据卷 |
| 2 | 后端日志 `MySQL 连接失败…已回退 SQLite`，`/health` 里 `database.engine` 是 `sqlite` | MySQL 未启动 / 地址端口错 / 密码错；`DB_BACKEND` 仍是默认但环境未就绪 | 这是**设计内的降级**，功能仍可用。要恢复 MySQL：`systemctl status mysql` 确认存活，核对 `.env` 的 `MYSQL_HOST/PORT/USER/PASSWORD/DB`，容器内必须写服务名 `mysql` 而非 `127.0.0.1` |
| 3 | 日志 `Redis 不可用`，`/health` 的 `cache.mode` 显示进程内缓存 | Redis 未启动或 `REDIS_URL` 错 | 设计内降级，接口行为不变（仪表盘 60 秒缓存仍生效）。恢复：`systemctl enable --now redis-server` 或 `redis-cli ping` 确认；容器内 `REDIS_URL` 应为 `redis://redis:6379/0` |
| 4 | 小程序报 `request:fail url not in domain list` | 未配置合法域名，或真机预览时仍用 `http://` / IP | 开发阶段在开发者工具勾选「不校验合法域名…」；正式版在公众平台配置 `https://<你的域名>` 到 request 合法域名（每月仅 5 次修改机会） |
| 5 | 真机连不上局域网 IP（超时 / `request:fail`），但电脑浏览器能开 | 未监听 `0.0.0.0`；防火墙未放行；手机不同网段；路由器 AP 隔离 | 后端启动加 `--host 0.0.0.0`；执行第 2.5 步防火墙规则；确认手机与电脑同一 WiFi；先让**手机浏览器**打开 `http://<本机局域网IP>:8000/health` 验证网络，再调小程序 |
| 6 | 上传报 `413 Request Entity Too Large` | Nginx `client_max_body_size` 太小 | `nginx.conf` 已设 `30m`；改后 `sudo nginx -t && sudo systemctl reload nginx`。若已改大仍失败，检查后端 `MAX_UPLOAD_MB`（默认 20）是否小于文件体积 |
| 7 | 上传被后端拒绝并提示类型/大小不合法 | 扩展名不在白名单（后端支持 md/txt/docx/xlsx 及常见图片），或超过 `MAX_UPLOAD_MB` | 改用受支持的格式；调大 `.env` 的 `MAX_UPLOAD_MB` 并重启服务（同时确认 Nginx 上限更大） |
| 8 | `/api/v1/ai/chat/stream` 无输出、前端一直转圈，最后一次性刷出全部文字 | Nginx 缓冲了 SSE；或中间有 CDN/代理缓存 | 确认 `nginx.conf` 中该 location 的 `proxy_buffering off; proxy_cache off; proxy_read_timeout 300s;` 生效；访问时不要经过会缓冲响应的 CDN；用 `curl -N -X POST https://<你的域名>/api/v1/ai/chat/stream -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" -d "{\"message\":\"你好\"}"` 验证是否为逐段输出 |
| 9 | 接口返回 401，提示 token 过期或无效 | `ACCESS_TOKEN_EXPIRE_MINUTES`（默认 10080 分钟 = 7 天）到期；或 `JWT_SECRET` 被改导致旧 token 全部失效 | 重新登录 `POST /api/v1/auth/login` 获取新 token；小程序端 `utils/request.js` 已内置 401 自动 `wx-login` 重登并重试一次；若改过 `JWT_SECRET` 属预期行为，所有用户需重新登录 |
| 10 | DeepSeek 返回 429 / 请求超时 | 触发平台限流（并发或额度）；单次请求超过 `DEEPSEEK_TIMEOUT`（默认 60 秒） | 稍后重试；调大 `.env` 的 `DEEPSEEK_TIMEOUT`；调小 `MAX_TOOL_ROUNDS`（默认 4）减少链路长度；检查平台余额；也可临时清空 `DEEPSEEK_API_KEY` 走演示模式保证功能可用 |
| 11 | 浏览器控制台报 CORS：`No 'Access-Control-Allow-Origin' header` | 前端域名不在 `CORS_ORIGINS` 里；或经 Nginx 反代后实际是**同源**却仍配了错误域名 | 把前端实际访问地址（含协议与端口，如 `https://<你的域名>` 或 `http://<本机局域网IP>:5200`）加入 `.env` 的 `CORS_ORIGINS`（逗号分隔，无空格），重启后端；注意：`allow_origins` 与 `allow_credentials=True` 不能同时用 `*` |

| 13c | 后端能启动，但上传/备份报 `Permission denied` | 服务以 `www-data` 运行，而 `uploads/`、`backups/`、`data/` 归属 root | `sudo chown -R www-data:www-data /opt/polaris-backend/{uploads,backups,data}` 后 `sudo systemctl restart polaris` |
| 14 | 前端刷新子路由（如 `/courses`）出现 404 | Nginx 缺少 SPA 回退 | 确认 `location / { try_files $uri $uri/ /index.html; }` 存在；前端用 `history` 路由时必须有这一行 |
| 15 | 页面样式错乱、白屏，控制台报 `/assets/xxx.js` 404 | `dist/` 上传不完整，或 Nginx `root` 指错目录 | 确认 `/opt/polaris-terminal/dist/index.html` 与 `/opt/polaris-terminal/dist/assets/` 都存在；`root` 必须是 `/opt/polaris-terminal/dist` |

## 附录 B：提醒推送链路（`scripts/push_reminders.py`）

**脚本确实存在于本仓库**：`polaris-backend/scripts/push_reminders.py`
（服务器上对应 `/opt/polaris-backend/scripts/push_reminders.py`）。

**它做什么**：扫描数据库中「即将到期的 DDL 任务」与「临近的上课时间」，
对每个命中项按用户剩余的一次性订阅额度调用微信 `subscribeMessage.send` 下发提醒，
并把每次发送结果写入推送日志表（用 `GET /api/v1/wechat/push-logs` 查看）。

**参数**：

```bash
python scripts/push_reminders.py              # 默认：DDL + 上课一起扫
python scripts/push_reminders.py --kind ddl   # 只扫 DDL
python scripts/push_reminders.py --kind class # 只扫上课提醒
python scripts/push_reminders.py --ahead 60   # 覆盖「提前 N 分钟」（默认 DDL 180 / 上课 30，见 .env）
```

**两种运行方式，二选一（不要同时开，避免重复推送同一用户）**：

| 方式 | 配置 | 适用 |
|---|---|---|
| 外部定时任务（**推荐**） | `.env` 设 `WX_SCHEDULER_ENABLED=false`，用 `deploy/push-reminders.cron`（自建服务器）或云托管定时触发器（第四章 4.4） | 生产环境；进程重启不影响调度，日志独立 |
| 进程内定时扫描 | `.env` 设 `WX_SCHEDULER_ENABLED=true`，`WX_PUSH_INTERVAL_MIN=10` | 本机/单机自用，省去配置 cron |

**演示模式**：未配置 `WX_APPID` / `WX_APP_SECRET` 时不实际发送，只写日志并打印
`! 未配置 WX_APPID/WX_APP_SECRET，本次只记录日志不会真实发送`。
链路可跑通、可验证，只是手机收不到消息。

**排查顺序（没收到提醒时）**：

1. `GET /api/v1/wechat/status` —— 看 AppID / 模板是否识别到；
2. `GET /api/v1/wechat/quota` —— 额度是否为 0（一次性订阅推完即失效，需用户再次授权）；
3. `GET /api/v1/wechat/push-logs` —— 看是否有 `success` / `skipped` / 微信 errcode；
4. 手动触发一次：`POST /api/v1/wechat/push/scan`（或 `POST /api/v1/wechat/push/test`）；
5. 服务器上直接跑脚本看控制台输出：`.venv/bin/python scripts/push_reminders.py --kind ddl`；
6. 检查 `.env` 的 `WX_MP_STATE`：填了体验版小程序却设 `formal`，消息会发到正式版而收不到。
